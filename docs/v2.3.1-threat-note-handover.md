## Hard-won facts (decompile- and runtime-proven — DON'T re-learn)

- **The writer "From" connection is a lazily-created Fact, and `Fact.isSeen=false` does NOT hide it.**
  A placed note gets exactly 2 facts, created **lazily on first examine** (allFacts is EMPTY right after
  placement — so any inject-time hide finds nothing): `FoundAt` (key=location) and **`From`** (preset name
  `"From"`, key=name, `GetOther(note) == writer.evidenceEntry`). Runtime diag proved the `From` fact
  rendered in the Connections tab **with `isSeen` already false** → isSeen is not the display gate.
- **FIX = REMOVE the fact, not hide it.** `ClueInjector.HideWriterConnection(docEv, person)` walks
  `docEv.allFacts` and `docEv.RemoveFactLink(f)`s any fact where `f.GetOther(docEv).Pointer ==
  person.evidenceEntry.Pointer` **or** `f.preset.name == "From"`. It's driven by a **Harmony POSTFIX on
  `Evidence.AutoCreateFacts(bool)`** (`Plugin.cs` `Patch_Evidence_AutoCreateFacts`), gated to
  `ClueInjector.AnonWriterNoteIds` (the tracked rent-note ids). **No hide-once guard** → it re-removes if
  the fact re-materialises; a genuine later handwriting-match creates the connection through a *different*
  path (not `AutoCreateFacts`), so the reveal is left intact. `Patch_Evidence_AddFactLinkExe` (private
  method via `AccessTools`) is a **log-only diagnostic** (fires per link on tracked notes).
- **Handwriting is a writer-FIELD trait, not a fact.** The note has no handwriting fact (only FoundAt+From),
  so removing the `From` fact keeps the handwriting sample. Handwriting derives from `writer.handwriting`
  (`HandwritingPreset.fontAsset : TMP_FontAsset`). SoD handwriting is **~6 shared TYPES**, so a match
  narrows the pool (killer included), not a unique ID — the intended soft lead. Can't self-verify without
  collecting the citizen's writing in-game.
- **Arrest ≠ death.** An arrested murderer **despawns** (`Human.removedFromWorld = true`, set via
  `RemoveFromGameWorld()`), but **`isDead` stays FALSE**. The game **never repopulates** dead/arrested NPCs
  (web-confirmed) — vacant landlord/job/apartment stays vacant. So `isDead`-only filters missed arrested
  NPCs. **FIX:** `removedFromWorld` is now checked alongside `isDead` in **every** actor-validity gate:
  `MurderSelector.IsValidActor`, `PropertySim.Alive`, `WorkplaceSim.Alive`. A despawned landlord/boss is
  never re-picked as killer/victim/anchor; their buildings simply drop out of the property pool.
- **Placement API:** `NewGameLocation.PlaceObject(preset, belongsTo, writer, receiver, …)` — the `writer`
  param sets the note's writer field (=> handwriting + prints); `receiver=null` → no "To" connection.
  `EvidencePreset.factSetup` entry `link==Subject.writer` is what auto-creates the `From` fact from the
  writer field (Angle A "clone-and-strip the preset" was the rejected fallback — it would kill the reveal).
