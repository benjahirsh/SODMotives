## What shipped

Two new `SocialEventType` members (append-only; persistence is name-based so old sidecars stay valid):

- **`Feud`** (`MotiveType.PersonalFeud`) — **bidirectional** bad blood between two citizens. Seeded from
  a genuinely **soured** directed `Acquaintance.like` edge (`< Motive.SouredLike`, 0.45). Either party
  can be killer or victim (`CollectFeudEdges` emits both directions).
- **`Debt`** (`MotiveType.Money`) — **one-directional** creditor-kills-debtor, mirroring `RentArrears`.
  Seeded over a real **social** acquaintance edge (friend/neighbour/coworker, `known >=
  NameKnownThreshold`); `a` = debtor (victim), `b` = creditor (lone suspect). Selector-starved by design
  (one suspect) — mainly enriches a debtor's MIXED pool, exactly like rent-arrears.

**Clues** (reuse the anonymous handwritten threat-note engine from v2.3.1):
- Debt → the SAME generic **"Settle your debt. Consider this your final warning."** note the verified
  rent-arrears case uses (generic wording reads for rent / loan / feud alike). Handwriting = creditor's
  own font, creditor's fingerprint, writer "From" connection removed.
- Feud → a new **hostile** note (**"You've had your last warning. Stay out of my way — or you'll regret
  it."**), handwritten in the **aggressor's** font + their print, writer connection removed. The
  aggressor for a given case = whichever feuding party ISN'T the victim.

**Gossip** (`SocialEvent.TestimonyAbout`) — **NAMES the other party** for both feuds and debts:
- Feud: *"Word is they'd had a serious falling-out with `<other>` — real bad blood there."*
- Debt: *"Word is they owed `<creditor>` money — hadn't been paying it back."* (subject = debtor) /
  *"`<debtor>` owed them money and had stopped paying up."* (subject = creditor).

## Key design decision to watch in playtest

**Feud/debt gossip names the other party** — a deliberate divergence from the *pointer-only* rule
workplace/property gossip follows. Rationale: feuds and debts have **no relationship anchor** the player
can follow (unlike landlord→residency or boss→roster) and **no identity-carrying clue** (their threat
note is anonymous handwriting), so the knower's testimony IS the only identity lead. This is consistent
with how affair gossip already names lovers, and sits inside V2.2's "variable specificity, weighted to
the knower's vantage" allowance (a close knower naming the party is the full-name tier). Every suspect is
named identically, so the killer reads no guiltier than a herring; forensics (print/handwriting/alibi)
still convicts. **If it feels too strong in play, dial it back** to a pointer in `TestimonyAbout`
(`SocialEvent.cs`) — rent-arrears was left deliberately vague there precisely because it HAS the
residency anchor, so the two money phrasings already differ by design.

## Persistence (no schema change needed)

Feuds/debts are seeded → live in `EventStore` → serialize via the existing **name-based `E`-line**
(`type.ToString()` / `Enum.TryParse`); one-to-one events have empty `group` and `companyId=-1`, so the
line format is unchanged and **pre-V2.4 sidecars still load clean**. Threat-note records use kind
`"rentdemand"` (debt) / `"feudthreat"` (feud); `RebuildCustomNote` rebuilds the right body and re-hides
the writer connection for both. The pool `PB` lines carry `PersonalFeud`/`Money` type strings that parse
back fine.
